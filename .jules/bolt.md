## 2024-10-31 - AppNetworkImage memory caching constraints
**Learning:** The `AppNetworkImage` component is used throughout the app for memory-bounded image decoding. Most implementations correctly set `memCacheWidth` and `memCacheHeight`. However, `FullBleedBannerSection` uses `AppNetworkImage` without setting `memCacheWidth` or `memCacheHeight`, which could cause memory bloat for the wide 2226x294 image.
**Action:** When using `AppNetworkImage` for wide banners (or in general), make sure to constrain the memory size to avoid unnecessary memory overhead, especially for high-resolution images like the 2226x294 stencil mask in `FullBleedBannerSection`. Since it's full bleed, the memory cache width should ideally be bounded by screen width. A safe max value might be based on common logical widths multiplied by device pixel ratio, or roughly 1000px, but wait, the aspect ratio is 2226/294. So setting `memCacheWidth: 2226` and `memCacheHeight: 294` would prevent loading even larger raw images (if they were somehow served larger) or we can cap it down.
